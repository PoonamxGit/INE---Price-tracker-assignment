# Design decisions

1. **HTTP plus Playwright.** The initial HTML is an empty React shell. Public metadata APIs are useful, but prices require pointer/dwell interaction and the store's own browser challenge exchange. HTTP is used for metadata; Playwright for price and stock. No undocumented price protocol is reimplemented.
2. **Recon shaped the design.** The store randomizes catalog pages, rotates price classes, hides decoys and can show provisional quotes. Ordinary pagination and the first price-looking selector are insufficient. See SCRAPER_RECON.md for observed endpoints and evidence.
3. **Asynchronous readiness.** Semantic buttons drive the page. Repeated cookie dismissal, real mouse movement, dropped-click handling and bounded refreshes lead to a completed quote. We never equate HTTP 200 or a populated container with a valid observation.
4. **Timeouts.** Each attempt has a configurable 45-second default deadline. Metadata fetches, browser navigation and intercepted requests use the remaining budget; the context is closed at expiry. Database leases are longer than the bounded three-attempt workload. Browser/context cleanup is in finally blocks.
5. **Retries.** At most three application attempts; exponential backoff plus jitter. Permanent missing-product/identity/configuration errors stop immediately. The store's internal retries are additional network events in diagnostics, not misrepresented as our application attempts.
6. **Validation.** Product ID, heading and SKU agree. Exactly one visible selling-price candidate is required. Currency and decimal strings are validated; null, negative and malformed prices fail. Known zero prices are permitted. Stock supports observed phrases; absent data fails and unknown quantity remains null.
7. **Failed scrapes never create history.** PostgreSQL `complete_attempt` atomically inserts history and updates attempt/product/run status. `fail_attempt` only updates logs/status. Unique run_id in history makes commit replay idempotent. A database failure escapes rather than becoming another scrape of the product.
8. **Honest logging.** The running attempt is inserted before network activity. Retries and final failures persist under one run ID. Pino also logs completion status, attempt, duration, product ID, URL and error category. Diagnostics contain paths/statuses, never session tokens. UI logs are paginated with local-time timestamps and expandable diagnostics.
9. **Scheduling.** External cron POSTs every two hours. SQL creates one durable cron job per UTC slot, snapshots active product IDs and acknowledges with HTTP 202. A bounded worker drains queued jobs on request/startup. Two SQL-controlled scraper slots protect manual, cron and headed triggers across processes. There is no application scheduling interval. Busy work returns to the queue; crashed jobs/runs recover through leases on a later wake.
10. **Free hosting.** Chromium needs OS dependencies, so Render uses Docker with the lockfile Playwright browser installed at build time. Free instances can sleep, cold start, lose memory caches and restart. A pre-wake job mitigates cron cold starts. Uninterrupted two-hour timing needs always-on hosting; the application does not claim otherwise. Twenty active products is an explicit demo capacity limit, not a throughput guarantee.
11. **Structure-change detection.** Missing previously observed containers, ambiguous candidates or invalid metadata schema are distinct from transport failures. Current layout classes corroborate a candidate; independent visibility/text filtering survives class rotation. Unexpected structures fail closed.
12. **Security.** IDs/URLs and API inputs are validated. Both HTTP and browser requests are restricted to the INE origin. Browser route fetching disables redirect following before fulfillment. Cron uses a constant-time bearer comparison. Supabase service-role keys remain server-side, tables use RLS with no browser policies, and mutating RPCs are revoked from public roles. CORS is configurable; actions/search are rate-limited.
13. **HTTP/browser trade-off.** Metadata discovery is deliberately light and shared, but shuffled pages require deduplication and explicit coverage. The browser costs memory/time but follows the real store logic. No browser camouflage or challenge forgery is used. Measured clock alignment fixes environmental skew inside the browser only.
14. **Next improvements.** Persist the catalog cache across replicas/restarts, add per-user authentication/ownership, add a dedicated always-on queue worker, use a server-supported stable catalog/search endpoint if one becomes available, add retention/archival for long-running deployments and validate Docker/hosted behavior under sustained load. Email alerts were omitted to keep reliability work focused.

The application is a shared assignment dashboard. The browser tests' embedded PostgreSQL/fixtures are test infrastructure, never a production fallback. Credentials and hosted verification remain separate from code-level/local evidence.
